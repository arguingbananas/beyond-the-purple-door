# Beyond Castle Wolfenstein: Purple Door Patch with Saved Game

`bcw-purple-door-with-savegame.ips` turns a **virgin copy of the 4am crack**
into a disk that:

1. contains the purple door patch described in `Purple-Door-Local-Patch.md`,
   and
2. holds a **saved game with the player in the terminal room (room `$3C`)**,
   so you can test the door without playing through the castle first.

The plain `bcw-purple-door-local.ips` contains only the patch (28 bytes). This
file adds the saved-game data and is the one to use when you want to start in
the terminal room.

## Size

| File | Bytes | Bytes of disk changed |
|------|-------|-----------------------|
| `bcw-purple-door-local.ips` | 51 | 28 |
| `bcw-purple-door-with-savegame.ips` | 634 | 409, in 23 groups |

The IPS merges changes that are within 5 bytes of each other, so a few
unchanged bytes inside a group are written back unchanged.

## Applying

1. Back up the original 4am image. Use a copy: IPS tools normally patch in
   place.
2. Apply `bcw-purple-door-with-savegame.ips` to the copy with any IPS tool.
   Do not apply the other IPS file as well. This one already contains the
   patch.
3. Boot the patched copy.

It only fits the standard raw DOS-order 4am image (143,360 bytes, SHA-256
starting `5898ae8f`). Any other image will be corrupted, because IPS writes at
fixed offsets. The Python patcher in `apply_bcw_purple_door_patch.py` is the
safer choice for other images, but it carries no saved game.

## Starting the saved game

At the title screen ("PRESS RETURN TO BEGIN"; if the attract demo is
running instead, press **Esc** first):

1. Press **Return**.
2. Press **K** (keyboard).
3. Press **D** (resume a saved game) and wait until option D is highlighted.
4. Press **Return**. Loading takes about 30 seconds.

The game resumes with the player in the terminal room. Walk to the purple
barrier. It is still drawn, but you can pass through. Outer walls, inner walls
and the green closets (they are closets, not doors) still block you.

Do not press Esc once the game is running. Guards in the room can also pass
through the opened barrier, so move to the door promptly. If you get caught the
game ends and the saved game in memory is lost; reload the patched disk and
begin again. Make a copy of the patched disk before you play, since the game
writes to its disk when it saves.

## What the IPS changes

### Patch data (identical to the patch-only IPS)

| Image offset | Length | Change |
|--------------|--------|--------|
| `0x17C02` | 1 | `@FHR` header length low byte, `A3` → `BB` |
| `0x186A7` | 24 | stub written at `$1EB3` in `@FHR` |
| `0x1AF31` | 3 | `^THINGS` `CA A5 6B` → `20 B3 1E` |

### Saved-game data

The rest of the changes fall in the three files the game uses for its saved
state: `SEKTOR`, `CASTLE` and `BACKUP`. They sit at these image offsets, as
`track/sector (logical)`:

| Disk area | File | Offsets (track/sector) |
|-----------|------|------------------------|
| `0x0610F–0x06247` | `SEKTOR` | T6 S1, T6 S2 |
| `0x07C32–0x07C9F+` | `CASTLE` | T7 S12 |
| `0x0A047`, `0x0A081` | `CASTLE` | T10 S0 |
| `0x0BE00`, `0x0BF00` | `CASTLE` | T11 S14, S15 (one full sector at `0x0BF00`) |
| `0x0BC40` | `BACKUP` | T11 S12 |
| `0x0E047` | `BACKUP` | T14 S0 |
| `0x0FF0D`, `0x0FF41` | `BACKUP` | T15 S15 |

These are the sectors that differ between the virgin image and the saved-game
image. Together they make up the saved game used during development. The
individual fields were not decoded.

## Provenance and verification

- The source was `Beyond Castle Wolfenstein - Purple Door Saved Game Local
  Test v3 Backup.dsk`. It was built from the 4am image plus the saved game
  state plus the purple door patch.
- The IPS was generated by comparing that image with the virgin 4am image.
  Applying it to the virgin image gives back the v3 image byte for byte.
- That v3 image was played in Apple2TS. The player walked through the purple
  barrier, and walls and closets blocked as expected.
- The pristine 4am image was never modified.

## Limitations

- Guards can walk through the open barrier as well.
- Only room `$3C` is affected by the patch.
- The IPS is only for the standard raw DOS-order 4am image.
- The saved game contains whatever state the original run had. It was not
  built to be a clean "new game in the terminal room" state.
- The IPS-built image was boot-tested (2026-11-20): applied to the virgin
  4am image, booted headless in Apple2TS, resumed with Return, K, D, Return,
  and it arrived in room `$3C`. It is also byte-identical to the v3 image
  that was played.
